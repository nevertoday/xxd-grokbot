Once this is set up, you'll get a link every Friday afternoon. Monday's deck is already built in the same shape as last week's, every number shows where it came from, and you change a few things and it's ready.

Your Fridays probably look the same every week: open several spreadsheets, copy the numbers into slides one by one, then fix the formatting against last week's deck. Get one number wrong and Monday's meeting spends ages arguing about it. So finished slides aren't really the result you want. What you want is for the numbers people see in the meeting to be right, so the meeting can be short and clear. <mark>What matters most is that every number traces back to a spreadsheet, and a number it couldn't get stays blank instead of being filled in with an old one.</mark>

## What you want is a number you can trust

Preparing slides for a weekly meeting is one of the goals the author, poteto, lists in the [article](https://x.com/poteto/status/2123159537016533493). The official docs have a similar example. The bot reads past decks in a folder, drafts the next one in your format, and leaves it in Drive for your edits. See [Use cases](https://docs.x.ai/grok-bot/use-cases#connect-your-apps-and-get-help-with-your-work).

Make a new <Term k="bot" />, call it Potato, and send it the goal:

<Copy id="ws-goal" title="First message: the goal" code="Hi Potato. I want the numbers people see in Monday's meeting to always be right, so that the meeting is short and clear and we spend the time making decisions. This is your job from now on, so remember it. Based on the goal, choose a name and a picture for yourself." />

## Tell it how you do it on a Friday

Next, tell it how you do this today. Pressing `Cmd/Ctrl+D` and talking is the easiest way, saying things as they come to you. Here's an example. Swap in your own folders and spreadsheets:

<Copy id="ws-process" title="Second message: your process" code={`Potato, here's how I usually do this myself. On Friday I pull this week's numbers from the spreadsheets and build a new deck in the same format as last week's. I add speaker notes to each slide and review the whole thing before Monday. Two things matter most to me: the numbers match the spreadsheets, and the number and order of slides stay the same as last week. Past decks are in Google Drive, the numbers are in Google Sheets, and project updates are in Slack. More specifically, the information comes from the "Weekly meeting" folder in Drive, the data sheets, and the project channels in Slack. How do I know it's right? Every number can be traced to a spreadsheet. For feedback, I look at what people asked in the meeting and which slides I changed.

Think about how you could take this over from me completely. Before you begin, restate my goal and process in simple words, so I can give you feedback and confirm it. Don't start doing the work yet. Let's get the process planned first.`} />

It restates what it heard first. Correct anything that's off and go a few rounds, then tell it to go ahead when you're happy. If it needs an app, it shows a **Connect** card in the chat. Open it and sign in.

## When two numbers disagree, which one wins

The author gives an example in the article. An email and your booking system show different appointment times, so which should the bot trust? You'd know without thinking, but it doesn't. Slides are the same. When someone in Slack quotes a number that doesn't match the spreadsheet, it has to know which one to trust and tell you about it. So give it your rules:

<Copy id="ws-judge" title="Third message: how you decide" code={`Potato, here are a few rules I use to decide. The spreadsheet is right about numbers, so if someone in Slack quotes a different number, use the spreadsheet and flag it in the notes for me. Only something that changed a lot since last week gets its own slide. Combine the rest. If you couldn't get a number, leave it blank and mark it "missing." Never reuse last week's.

Then help me find what I haven't told you about this process yet. Ask me how I make decisions, where I get my information, how I check the work, and when you should come to me. Ask one question at a time. Then walk me through a few examples so I can give you feedback. Don't automate anything yet.`} />

The last rule matters most. A blank cell marked "missing" tells everyone at a glance to ask about it. A number borrowed from last week gets taken as real. When you pick examples, include one or two that went wrong, like the week a slide didn't match the spreadsheet. See how it would handle them, then tell it what to fix.

## Let it have the deck ready every Friday

Once this has gone well a few times, it can start on its own. Save the process as a <Term k="技能" /> first, then set up a <Term k="routine" /> so it starts on time every Friday:

<Copy id="ws-routine" title="Fourth message: let it start on its own" code={`Save the process we just worked out as a skill called "Weekly slides." Then set up a routine: every Friday at 4:00 PM, use that skill to build Monday's deck. Save it in the "Weekly meeting" folder in Drive with the date in the file name, and send me the link. Don't send it to anyone else. If a spreadsheet won't open, flag it on that slide. Don't use old numbers.`} />

After the first few runs, check its work. Pick three numbers and compare them with the spreadsheet. See that the slide count, order and template match last week's. Then make sure the new file is in the "Weekly meeting" folder with the date in its name.

A new routine waits for its next scheduled time. To try it now, open it and choose **Test**, but know that a test does real work. See [Create a routine](https://docs.x.ai/grok-bot/skills-routines-and-automations#create-a-routine) in the official docs.

To have it send the deck to colleagues, ask for a draft first. To see what it stops to ask you about first, read [Approvals and privacy](/en/howto/approvals-privacy/).

## Stuck?

<Q q="The deck doesn't look like our template.">
Point it to the template file or last week's deck and say "always follow this one from now on," then ask it to remember that.
</Q>
<Q q="Drive has several files with the same name.">
That's because saving to Google Drive always creates a new file, even when one with that name exists. Ask it to put the date in the file name, and you'll be able to tell the weeks apart.
</Q>
<Q q="One of the numbers is wrong.">
Ask it to keep three things apart: what it found in the spreadsheets, what it worked out itself, and what it couldn't check. Then ask for the source of each number, and you'll see which step went wrong.
</Q>
